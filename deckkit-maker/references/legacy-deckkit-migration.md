# 已有 DeckKit 的合同迁移

沿用入口 SKILL 的两阶段流程和 [设计源迁移](design-source-migration.md)、
[视觉验收](visual-acceptance.md)，本文件补充已有调用方和旧资产的退役边界。

## 1. 冻结真实基线

- 记录起始 commit、现有 catalog/版本、实际 runtime 和字体；重跑 smoke/public audit。
- 对旧源码、schema、build 胶水、catalog、示例、动画 target、图片槽位、theme/style pack、
  翻新配置与 showcase 建立引用清单。只读参考、用户 deck、无关运行证据不进入删除清单。
- 逐张查看全部参考页和同环境的旧 canonical 页，登记缺陷。旧 pass 摘要不能覆盖实际缺陷。
- 原始参考和旧套件可能具有不同页数或顺序；建立“原始页 → 旧页 → 新职责”的映射，
  区分原始内容、旧版补入的职责和遗漏的细节，不用旧 showcase 页数覆盖第一手事实。
- 先在当前 run 建立并验收视觉基线，再冻结正式合同。历史文档只提供线索，实际能力以本次运行时为准。

## 2. 收敛到一个执行路径

- 保留 id、公共 createDeck 接口和有效页型职责；字段变化写明确映射。单位/来源未知时失败，
  不从模板猜测业务事实，不用旧 readiness 给重写实现背书。
- 合同承载角色、颜色、字体、几何、容量和规则；解析器生成组件计划，组件执行器消费计划。
  优先复用共享断言、选择、计划/patch 哈希和原生回读；只有新语法需要时注册新视觉族。
- 不用宽松 fallback 绕过非法输入；可选控制字段必须真的改变行为或明确报错。
- 预算投影保留资产槽位、翻新映射等独立能力。先测试投影不会丢失元数据，再清理旧代码。
- 编号和短圈内文字由形状自身拥有，设置水平/垂直居中。原生段落 target 和 level 有调用方时须保留并回读。

## 3. 覆盖最终源码

- `auto` 成功只证明所选布局。为每个注册布局提供合法显式探针，检查实际 frames、构图指纹和渲染；
  再测最大合理密度、最小内容、中英混排和明显不同领域内容。
- 最小内容探针遍历全部可见字段，确认没有参考文案泄漏；圈内哨兵须符合真实字符容量。
  控制字段可免可见槽位探针，但须有独立正负行为测试。
- 图标、匹配词等语义控制不能填入任意哨兵：可选匹配词使用现有 control omission，
  必须提供合法标识的控制使用 `x-slotProbeValue`；该注解只允许 control 字段。
  数值探针遵守 schema minimum/maximum，嵌套覆盖须用 fallback probe 验证根字段仍能显示。
  这些探针配置不代替真实图标、强调效果和数值派生的行为测试。
- 静态检查为零仍可能发生 PDF 最终排版溢出。定位拥有文字的 frame，修正实际几何或行高估算；
  不得放宽门禁或无限缩字。修后重生成受影响样例并查看同类组件。
- 每张准备接受的最终 canonical PNG 都要实际查看，contact sheet 只检查整套节奏。
  保存候选、patch、完整计划和 PNG 哈希。若代码变化但输出未变，明确重生成并比较 patch/完整计划，
  证明绑定仍成立；否则生成新候选和新证据。
- 原生打开、另存、关闭重开之外，新能力组合还需代表对象编辑验证：修改普通文字、
  形状自带文字或内嵌图表数据，保存重开并独立回读。打开了编辑菜单不等于编辑成功。
  不把机器、视觉或宿主之一的结果当成另外两项的证明。
- 可选像素诊断要先验证自身探针：单像素宽的真实字形不能被当成空白，临时遮罩不能与深色字形混淆。
  诊断仅作辅助；最终图片仍是视觉判断依据。

## 4. 退役与发布记录

所有阻塞缺陷关闭、最终源码绑定且适用宿主通过后，替换旧示例、showcase、baseline 和质量记录，
删除仅为旧路径服务的源码/资产/失效引用。不要建立永久 legacy 分发目录。
有效的 theme/style/nativeSkinning、用户资料和历史失败证据不因创建链迁移而删除。

运行投影/槽位一致性、针对性测试、smoke、严格公共审计、目标 readiness；共享门禁变更还需共享回归。
报告删除/替换/保留清单、机器/视觉/宿主证据路径和未验证项。目标是 candidate 时保持 candidate；
不得用示例成功声称自动生产交付、任意输入无损翻新或全平台字体一致。

## 5. 组合探针与原生表格的容量

- 矩阵位置等数组控制字段若用同一个探针值，会构造出重叠的非法样例。
  对 `x-slotRole: "control"` 的数组条目字段，可用 `x-slotProbeSequence: [0.25, 0.75]`
  按条目索引取值；不能与 `x-slotProbeValue` 同时声明，也不能用于可见文字或数组外字段。
  该注解只修正合法探针，不能豁免真实坐标、图标和数据的行为验证。
- 文本容量的分配区域与最终文字框应分别记录。顶对齐文字可以在容量核对后，将输出框高度
  收到已估算的文字高度，并在组件计划保留 `allocatedFrame`；有文字的编号/标签容器仍保留
  完整 frame 与双向居中。不要因为静态框碰撞就缩字号、压行高或跳过实际 PNG 检查。
- 原生表格的 `add-table` 必须显式给出 `rows`、`columns`，不能只提供 `data`。
  单元格文字长度告警与逐实例几何都应在执行组件中提前阻断；依据本次 runtime 探针声明
  合法容量，选择另一构图、重组或按授权改写输入，不能在渲染函数里截断内容。
  表格变体与其他构图应使用同一份最终 content，逐格回读全部内容，并做原生编辑验证。
- 多段落单元格的样式不能只凭静态 vision=0 判定。此次迁移出现后续段落在 canonical PDF 中
  字号变大、越界的失败样本，尚未归因到 renderer 或宿主；改用单个明确样式的段落和行内分隔后，
  canonical 与 PowerPoint 保存重开均通过。若确需多段落，逐段显式设样式并重新看最终候选。
  原生编辑测试应选中单元格内部文字；双击列边可能触发列宽调整，须区分操作副作用与生成缺陷。
