# 从 design.md 与参考图迁移设计语言

此路线用于创建/扩展 DeckKit，最终通过 pptx-nova 标准 validate/build/create runner 使用。
参考可以是多页合成图、单页图片、多张截图或风格板；只有这些材料时，不要求额外的 HTML/PPTX。

## 输入事实与裁决

使用会话已确认的 kit 名称和授权。保存文档/图片 hash、尺寸、页型和特征清单；先看原图，
再看关键局部。缩略图不可读的数字不能靠猜测补全。

可选维护者助手（Node 内置模块；仅 `--crop` 可选使用 ImageMagick）：

```bash
node deckkit-maker/scripts/analyze-design-source.mjs \
  --id <id> --design <design.md> --image <reference.jpg> \
  --panels <vertical-panel-count> --crop --out <run>/source-analysis
```

输出目录必须新建。`--image` 可重复；`--panels` 仅用于单张纵向合成图。等高分割是建议，
必须看图确认边界；带导航、间隔、非等高页时改用人工记录边界。助手只分析 PNG/JPEG 尺寸与 hash，
不声称理解设计、识别业务数据或验证 EXIF 方向。可选裁图不可用时保留原图审查。
原图只读，裁图保留在 run；不能将截图用作 PPTX 全页背景。

设计文档可能混入另一份源稿的比例、字体证明或组件清单。先为冲突建立四列记录：

| 文档断言                | 实际图像／源文件观察                   | 裁决及理由                         | 合同／验证影响                     |
| ----------------------- | -------------------------------------- | ---------------------------------- | ---------------------------------- |
| 示例：17:11，且无数据图 | 合成图按八个 16:9 页面切分，存在比例条 | 使用用户要求的 16:9 与实际证据语法 | 时间／数值模型、原生回读与逐页验收 |

只拥有图片时，不把文档声称的“PDF 嵌入字体已验证”写成本次已验证事实；字体来源、系统解析、
canonical 实际渲染和 PowerPoint 宿主验证分别记录。面板等分边界仍须逐页看图确认。

记录 `style-spec.md`、`slide-inventory.md`、`compare-notes.md`，明确：

- 身份不变量：颜色职责、文字角色、对齐、页脚、特征组件、禁用效果。
- 构图空间：证据对象、区域关系、容量、可变布局、密度和跨页职责。
- 软偏好：深浅页比例、节奏、留白；不为凑比例编造页面或改变用户内容。
- 冲突优先级：用户明确要求优先；规范内部的覆盖关系其次；截图的近似采样和布局作为视觉依据。
  优先级不明确时，作出可解释的设计决定并记录，不默默忽略冲突。
- 可读性适配：实际字体、字号、对比度、中文换行、图表标签。修正不合理参考，记录哪些变化
  属于用户授权的设计改进，哪些仍需内容授权。

背景装饰也可能是身份，不要只盘点文字、图表和表格。逐页记录椭圆、叠层、裁切、纹理、
渐变及位置关系；若它们构成参考的辨识度，应进入 signature inventory 和生成回归。
不要仅因通用的“零装饰／极简”默认规则就删除风格专属背景，也不要把核心叠层默默降为软偏好。
规范内部冲突时写明裁决；用户明确要求保留时，以其要求为准。优先使用原生可编辑形状，
并以画布裁切后的实际几何验证边界、层序与文字对比。用户指出遗漏后撤回受影响的旧视觉结论，
修复全部同类页面，再生成同一新候选的逐页证据。

在 `slide-inventory.md` 中给有辨识度的细节建立对应关系：参考页/局部、颜色与字重、几何关系、
执行组件、最终 PNG 的复核位置。除了大块构图，也检查导航圆点、短划线的粗细、基准刻线、
虚线引线、行内注记、月份刻度、依赖说明，以及背景和画布边缘的衔接。只统计组件存在不够，
还须看它在实际画面中的长度、位置、层序和相邻留白。用户强调风格细节时，把这些对应关系
作为基线验收项；不要在抽象组件时默默把它们省成普通标题、数据和矩形。

贴底、出血或裁切图形应记录实际可见边界，尤其核对“贴画布底边”与“贴底栏上沿”的差别。
从同一候选 PNG 放大检查交界，避免留下原稿没有的白缝。为已确认的几何关系补回归断言；
断言和机器门禁仍不能替代逐页看图。用户指出细节遗漏后，撤回受影响的完整性结论，并检查
其他页及所有合法变体是否也省掉了同类细节。

## 分开皮肤与领域政策

视觉身份不应自动插入投资判断、估值模型、医疗结论或业务叙事。领域政策放在独立参考中，
说明何时显式采用。正文断言、单位、来源、日期、假设、阈值和风险文案来自 content。

示例数据应明确是参考摘录还是合成测试。图片不够清晰时，用可追溯的合成样例检验风格，
不伪装成真实市场事实；也不把金融政策强加给使用相同皮肤的非金融内容。

## 建立视觉证据，再冻结公共合同

覆盖材料中有复用价值的页型与 signature。设计迁移以来源页型和视觉语法为覆盖基线；
用户要求高保真重建时按主 skill 的 full/scoped 约定执行。风格板没有明确页序时，
构造覆盖清单，不虚构“原始页数”。用户允许优化时，以合理设计为准，不锁住明显缺陷。

先验证代表页的 patch、实际对象和 canonical PDF/PNG，再完成约定范围逐页审查。
比较参考与生成图的层级、阅读路径、可读性和身份特征，记录有意差异。
没有可接受的视觉基线，不冻结为已验证套件。
按 [visual-acceptance.md](visual-acceptance.md) 逐页记录；圆形内文字、标签底条和表格附注须
局部放大核对。参考图的缺陷可以改进，迁移产物自身的细节缺陷不能因风格相似而被接受。

## 合同与执行边界

读取 `pptx-nova/references/create/design-contracts.md` 与 `schemas/design.schema.json`：

- JSON 定义 tokens、角色、硬规则、容量、注册构图；intent.md 解释判断，数值保持一个事实源。
- 复用字体/theme、合同检查、确定性布局选择、原生数据回读、交付绑定等共享能力。
- 共享内容语义与安全能力，不强迫不同设计语言使用同一套卡片。选择已注册视觉族；确需新语法时
  扩展边界清楚、参数受合同控制的组件，不给新风格复制全部执行器。
- 字数/行数是候选筛选估计，最终以实际渲染为准。无布局容纳时明确失败/拆页，不无限缩字。
- 图表/表格优先原生。进度条/点图可以是数值派生的可编辑形状，但须披露实现和回读边界。

新证据能力先做最小探针：schema → dry-run → apply → inspect/model → render。
检查所有系列与所有单元格，不只数对象。若投影遗漏 combo 系列等关键语义，验证条件不成立；
选择能完整验证的表达，或明确未验证边界。不要将某次运行时限制固化为永久禁令。

## 冻结与复用验证

- 输入 schema、catalog 必需槽位和实际可见内容一致；字段先注册再消费。
- 数值存在跨字段关系（例如期初 + 差异 = 期末）时，可在数值 schema 使用有限的
  `x-slotProbeValue` 提供合法探针样本，不必将业务数值伪装成 control 或改变真实数值范围。
  该注解不能替换可见字符串哨兵；真实数据、零/负值、密度边界及不一致反例仍须另测。
- 有互斥可选组件时，schema 可声明 `x-slotProbeVariants: [{"omit":["optionalField"]}]`，
  按合法组合审计。只可省略可选顶层字段，每个声明字段必须至少被一组探针覆盖。
- 嵌套的可选控制字段互斥时，可标记 `x-slotProbeOmit: true`；只允许可选且
  `x-slotRole: "control"` 的字段，不允许跳过可见文字或必填控制。被省略控制必须另由真实输入、
  边界和反例验证。探针配置错误必须让命令失败；不能把未完成审计当成无 ghost slot。
- 数组项控制值有互异或分组约束时，可用 `x-slotProbeSequence: [0, 1]` 按项索引生成合法
  探针，例如事件索引或分组编号。它仅用于数组项的 control 字段，不能与 x-slotProbeValue
  混用，也不能代替可见字符串哨兵。真实顺序、越界、重复及缺组反例仍须另测。
- 同内容至少两种真正不同的合法构图；比较实际几何，不靠 layoutId 改名。
- 反例覆盖未知规则、错误色/字体、第二焦点、来源/单位缺失、过量内容、重复构图、零/负/缺失值。
- 用 CJK/Latin、短/长标题、稀疏/密集证据和不同业务主题检查泛化。硬规则须有检查器；
  审美、像素面积、断言质量等未自动证明的项目明确进入视觉复核。
- 回归之前迁入的合同风格；新套件默认推进 candidate，未经授权不提升 production。
- golden 入库，stress/mixed 临时证据保留。标准 canonical Create 与逐页复核不能由历史 baseline 替代。
- 记录“共用了什么、增加了什么、仍然专用什么”，用实际第二种/第三种风格检验抽象。

Black Gold 的经验不是所有风格的固定模板：它采用深色判断、灰阶证据、单焦点、原生矩阵和
当前运行时可完整回读的双单位对齐图。后续风格应从自己的规范重新提取身份与构图。

Clear Value 迁移暴露了几个边界：通用 schema 中存在标签字段，不代表每种经典图表都支持它；
先做实际探针。原生 doughnut 的 JSON 投影名可能是 ring，只在确认当前 runtime 后归一化
明确别名，不能放松类别/系列/数值比较。图表头由系列名、首末类别与数值组成时，必须按组合
后的真实文字检查容量。动态列宽/多图布局不能仅靠每个字段的固定字数预算证明可读。
